1
Dirección técnica / Producto

Fijar los modelos Kimi y DeepSeek

Decide exactamente qué modelo se utilizará: repositorio, revisión o commit y archivo concreto de pesos.

  • Kimi necesita revisión, artefacto, digest y texto de licencia.
  • DeepSeek necesita además una expresión de licencia SPDX válida.
  • Calcula SHA-256 del artefacto y del texto de licencia.
Terminado cuando: no queda ningún TBD de Kimi o DeepSeek en el lock candidato.

Terminado cuando: desaparece installed-runtime-is-fixture y existe una prueba funcional controlada.

DevOps / Registro OCI

Publicar las siete imágenes Atlantis

Publica crm-api, marketia-adapter, model-gateway, orchestrator, policy-gateway, voice-adapter y whatsapp-adapter en el registro aprobado.

  • Usa etiquetas inmutables para RC5.
  • Obtén el digest del manifiesto remoto, no el ID Docker local.
  • Sustituye cada local-docker:// por una referencia con @sha256:….
Terminado cuando: CI puede descargar las siete imágenes por digest.
4
Legal / Open Source

Revisar licencias

Empieza por LEGAL_REVIEW_QUEUE.json. Verifica 38 paquetes Python y resuelve las 1.511 combinaciones paquete/versión sin licencia declarada de las imágenes.

  • No aceptes automáticamente NOASSERTION.
  • Conserva texto, procedencia y SHA-256 de cada licencia.
  • Determina avisos y obligaciones de fuente correspondiente.
  • Registra quién revisó cada decisión.
Terminado cuando: ningún SBOM contiene NOASSERTION y Legal acepta inventario y avisos.

6
QA / Release

Construir el artefacto final inmutable

Ejecuta las pruebas, crea el paquete exacto que recibirá el cliente y calcula su SHA-256. No lo modifiques después.

python3 -m unittest discover -s tests -q python3 tools/compliance_gate.py --mode source sha256sum /ruta/al/artefacto-final
Terminado cuando: pruebas y gate pasan, y el artefacto tiene ubicación y hash definitivos.
7
Release + Security + Legal

Crear evidencia final y firmar

CI debe crear en release/evidence/ los SBOMs, avisos, licencias, fuentes, lock y attestation finales. Aprovisiona las claves públicas confiables en release/trusted-signers/.

Cada responsable firma criptográficamente subject y artifacts. Las firmas deben cubrir el artefacto entregable y todos los hashes finales.

No reutilices hashes del candidato si cualquier archivo ha cambiado.

Terminado cuando: existen firmas válidas e independientes de Release, Security y Legal.

Release Manager

Ejecutar el gate final

python3 tools/compliance_gate.py --mode distribution --artifact /ruta/al/artefacto-final

Solo distribuyas si termina exactamente con COMPLIANCE GATE: PASS (distribution). Si falla, corrige la causa; no alteres el gate.

Terminado cuando: el gate pasa contra el mismo archivo que recibirá el cliente.
